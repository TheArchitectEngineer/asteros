Build log

Nineteen phases.
Every one verified live.

A phase isn't marked done from a clean compile — it's done when it boots in QEMU and the full regression checklist from every earlier phase still passes. This is that log, straight from the project's own TODO.md, including the real bugs found on the way and the v1 gaps left honestly documented.

PHASE 01 Workspace & sources
done

xnu-6153.141.1, dtrace-338.100.1, AvailabilityVersions-45.11, libplatform-220.100.1, libdispatch-1173.100.2, and Libsystem-1281.100.1 cloned into src/, pinned to the exact apple-oss-distributions tags for this Darwin 19 era. A local SDK copy lives at build/SDKs/MacOSX10.15.sdk — cloned from the host's modern SDK and header-patched, since no real Catalina SDK exists on a current macOS host.

PHASE 02 Build the XNU kernel
done

A from-scratch clean rebuild (BUILD/ deleted, rebuilt from nothing) exits 0 with zero make-error markers, producing a 14MB Mach-O 64-bit x86_64 kernel.development with _pstart/_slave_pstart/_vstart present. Getting there took 14 source patches.

  • The deep one: xnu's real x86_64 entry point loads absolute addresses of high-canonical-but-physically-low symbols truncated to 32 bits — an intentional pre-paging idiom modern ld now hard-rejects with no linker-flag escape hatch. Fixed at 9 call sites, including a direct far-jump with no relative form, using only relocation kinds the linker accepts — verified to produce numerically identical runtime values.
  • ~20 new clang-21 default-warning categories that didn't exist when this xnu version was written; an obsolete clang flag; NFS and netboot compiled out entirely (out of scope, and failing dozens of new warnings-as-errors).
  • Real, pre-existing upstream bugs fixed, not just modernized: undefined PCI-config identifiers in cpuid.h/hpet.c, a missing comma silently concatenating two malloc-zone name strings, a NULL-vs-bool argument bug in IOPMrootDomain.cpp.
PHASE 03–08 Boot to console, root filesystem, tiny userspace, init & shell
superseded

The original plan tracked these as separate milestones: boot past IOKit's platform-expert matching, a MOCKFS + RAMDisk root filesystem, a tiny raw-syscall userspace, then a minimal init and interactive shell. Real, hard bugs were root-caused along this path — a missing device-tree "name" property making /chosen unreachable, an EFI runtime-memory collision clobbering the low identity map, a boot-thread stall inside IOService::doServiceMatch().

Rather than finish this path literally, the project jumped straight to real upstream BusyBox on a real FAT16 root filesystem (Phase 09) once that became the more useful target — a from-scratch libc, a real filesystem driver, and a genuine PID 1 subsumed everything these phases were meant to deliver. Kept here for the historical record, not as open work.

PHASE 09 Real upstream BusyBox as PID 1
done

Genuine, unmodified BusyBox 1.36.1 (ash + ls cat echo mkdir rm pwd uname, statically linked, CONFIG_STATIC=y) running against a from-scratch libc built specifically to give it a POSIX surface — no dyld/Libsystem dependency at the base layer. Boots to a live interactive shell, verified with mkdir/cd/echo > file/cat/rm all working end-to-end in one boot session.

  • Missing carry-flag check on every raw syscall — the real xnu ABI signals errors via the carry flag with a positive errno in %rax, never negated. Every syscall wrapper only ever read %rax as a return value, so every error was silently misread as a small "successful" result. This was the central diagnostic breakthrough that unblocked most of what came after.
  • FAT16 file fragmentation from repeated in-place image overwrites broke the driver's contiguous-cluster assumption, manifesting as a page fault deep inside BusyBox's own main() — root-caused via disassembly, not guessed.
  • getcwd(NULL, 0) unsupported (a glibc/BSD auto-allocate extension ash's pwd builtin relies on); GETOPT_RESET() hardcoded glibc-style reset semantics our getopt() didn't honor; a readdir() buffer overrun reading past the real d_reclen.
  • Full read/write VFS support — mkdir/create/write/remove/rmdir — implemented from scratch in fat16lite, including fixing a hardcoded root-mount MNT_RDONLY and a stale read-only-era lookup check.
PHASE 10 Native Clang/LLVM toolchain
in progress

The current frontier: clang hello.c -o hello && ./hello running natively on AsterOS, not just cross-compiling for it. Sourced from llvm-project (sparse checkout, pinned at llvmorg-20.1.8), built incrementally: compiler-rt → libc compat → libunwind → LLVM support libs → Clang frontend → lld, one link/run-verified step at a time.

  • Step 1, done: compiler-rt's soft-arithmetic builtins (__divti3, __udivdi3, __multi3, 128-bit int/float ops) — the first link-time blocker for any userspace C program, ahead of anything AsterOS-specific. Built standalone via compiler-rt's own CMake; verified via lipo/nm to contain real, correctly-named x86_64 Mach-O symbols.
  • Next blocker: libc compatibility for what LLVM's own support libraries need beyond today's libc — real nanosecond-resolution time, and an open question on whether a minimal pthread shim is needed for the build itself.
PHASE 11 dyld — the dynamic linker
done

Not the deferred-forever stub the original plan called for — a real dyld, from scratch. Loads dependencies, rebases, binds (both eager and a real lazy dyld_stub_binder path), and resolves symbols via the export trie. The kernel side needed zero changes: load_dylinker() was already fully correct, ground-truthed by reading it before writing a line of dyld code.

  • The one real bug that mattered: mach_loader.c always ASLR-slides the dylinker, regardless of MH_PIE or a -no_pie link. dyld therefore has to be genuinely position-independent — every internal reference RIP-relative, correct at any load address with zero self-fixups. Needed both -fPIC and explicit hidden visibility on every cross-TU extern.
  • Verified live: a normal executable with real LC_LOAD_DYLINKER and LC_LOAD_DYLIB boots, loads a dylib, calls a function and reads an exported const char * correctly — across multiple runs with different kernel-chosen ASLR slides in one boot session.
  • Known v1 limits: fixed 256MB dylib slots, no @rpath, no weak symbols, no mprotect re-protection after fixups.
PHASE 12 libSystem.dylib
done

The raw-syscall libc, compiled -fPIC and linked -dynamiclib, exporting 568 symbols at /usr/lib/libSystem.B.dylib. The real design problem: __libc_start can't live inside the dylib, since main only exists once the final executable links — split into a tiny per-executable libc_start.o, matching Darwin's real crt1.o/libSystem division.

  • The self-link quirk: ld64 refuses to build a dylib with an empty dependency list — including libSystem.B.dylib depending, nominally, on itself. Solved with a placeholder self-link stub; dyld's own image cache means this never becomes real recursion at load time.
  • Verified live: printf, malloc/free, and a fork()/waitpid() round trip all running through real dyld rebase/bind — plus every earlier regression test (dyntest, the full BusyBox checklist) reconfirmed passing.
PHASE 13 libobjc.A.dylib
done

A real Objective-C runtime targeting the genuine nonfragile-ABI2 on-disk layout — ground-truthed field-by-field against otool/objdump on a real compiled probe, not written from memory. dyld gained two small extensions: running a dylib's own mod-init-funcs at load time, and a hardcoded post-bind hook that calls libobjc's __objc_init.

  • Class realization was completely broken until a tagged-pointer scheme (low bit of class_t.data) distinguished real states — data is never NULL, so the naive "already realized" guard was true from the first call, and objc_getClass returned NULL for every class despite valid metadata.
  • Ivar offset patching at realization time is not optional under nonfragile ABI2 — missing it crashed on the first inherited-ivar property access.
  • ARC's autoreleased-return-value fast path is a real correctness requirement, found via a double-free: an autoreleased value immediately claimed by its caller needs its pending pool release canceled while still recording a real extra retain, or either half double-frees or under-retains.
  • Verified live: a subclass with an ivar-backed property, a category adding protocol conformance, [super init], ARC-managed alloc, and an explicit @autoreleasepool block — plus dyld's and libSystem's own regression tests, unregressed.
PHASE 14 launchd
done

Real PID 1 at /sbin/launchd, replacing the earlier tiny init launcher. A hand-written recursive-descent XML plist parser drives daemon supervision from /etc/launchd/daemons/*.plist: RunAtLoad, throttled KeepAlive respawn, orphan reaping via wait4(-1, …), and a bounded SIGTERM-driven shutdown into reboot(RB_HALT).

  • A runaway respawn storm — a daemon that exits in under a millisecond, re-forked thousands of times a minute — fixed with a measured ~500ms per-daemon throttle, confirmed against real log timestamps (565ms observed), not host-clock guesses.
  • Console flooding even after throttling, fixed by splitting routine per-daemon logging (file-only) from launchd's own lifecycle events (file + console).
  • The serious one: kill -TERM 1 during a throttle sleep interrupted an in-flight sigsuspend() with SIGTERM instead of the expected SIGALRM, leaving a still-armed timer that fired moments later and killed launchd itself via default SIGALRM handling — a full kernel panic, since xnu treats PID 1 exiting as always fatal. Fixed by unconditionally disarming the timer before restoring the old handler, regardless of why sigsuspend() returned.
PHASE 16 Real pthreads
done

Genuine kernel-scheduled threads, replacing a stub where pthread_create() honestly returned EAGAIN. The surprise: xnu-6153 doesn't implement bsdthread_create/psynch_* itself — those syscalls dispatch through a function table a separate pthread.kext is normally supposed to fill in. Fixed by vendoring the real, era-matched Apple libpthread kernel component directly into the kernel image, same pattern as fat16lite.

  • Two identically-named, differently-shaped struct ksyn_waitq_element definitions collided once compiled into one image — the real one had to be forced to win the include-guard race.
  • A genuine object-file basename collision silently dropped the vendored file from the build entirely (xnu flattens every object to its basename); a duplicate sysctl registration caused a live panic, confirmed via serial console and backtrace.
  • Mutex/condvar/rwlock are plain atomic-CAS spinlocks, not real psynch-backed kernel waits — correct under xnu's real preemptive scheduler, just less efficient. A documented v1 simplification, not a fake.
  • Verified live: 4 real threads incrementing a shared counter 200,000 times each under a mutex land on an exact 800,000 — zero lost updates under genuine concurrent execution.
PHASE 17 CoreFoundation
done

A real object model and collection library, pure C with no libobjc dependency — CFBase, CFAllocator, CFString/CFMutableString, CFArray, CFDictionary, CFSet, CFNumber, CFBoolean, CFNull, CFData. Deliberately out: CFRunLoop, CFBundle, networking types, CFPropertyList/XML, and internationalization types.

  • Two documented storage tradeoffs: CFString is UTF-8-backed instead of real UTF-16 UniChar buffers, and CFDictionary/CFSet are O(n) linear arrays instead of hash tables.
  • CFStringCreateWithFormat rides on the real libc vsnprintf — which surfaced a real, pre-existing gap: zero floating-point conversion support. %f/%e/%g silently didn't consume their va_arg, desyncing every argument after. Caught live, documented, not this phase's bug to fix.
  • Verified live: creation/mutation/comparison/format for every type above, plus a direct retain-count walk (1 → 2 → 1 → 0) confirming real refcounting, not a no-op.
PHASE 18 Foundation
done

Real Objective-C classes wrapping CoreFoundation via genuine toll-free bridging — NSString, NSArray, NSDictionary, NSSet, NSData bridged to their CF counterparts; NSFileManager, NSError, NSException, NSNotificationCenter, a minimal poll()-backed NSRunLoop, NSKeyedArchiver, JSON and property-list serialization, and NSUserDefaults as plain NSObject-backed classes.

  • A cross-image const NSString *const global written from a constructor read back stale in a different final executable linking the same dylib — fixed by dropping const on every such Foundation constant.
  • Chasing NSUserDefaults's disk persistence surfaced three real, separate fat16lite bugs: VNOP_CREATE only succeeding one directory level below the volume root, a stale cached vnode handing back the wrong type after a directory-to-file slot reuse, and a real disk write that reproducibly hung the whole process — documented, not chased further this phase.
  • A fourth finding: a very tight KeepAlive respawn loop can starve a slower co-resident daemon of scheduling time almost entirely — a real, previously-latent launchd/kernel fairness gap only a slow-enough daemon could reveal.
PHASE 19 libdispatch (GCD)
done

A real, v1-scoped Grand Central Dispatch on top of Phase 16's kernel-scheduled pthreads: serial and concurrent dispatch_queue_t, dispatch_async/sync (+ function-pointer variants), dispatch_once, semaphores, groups, and dispatch_after. Real Apple BlocksRuntime source now also builds into libSystem.B.dylib itself.

  • sysctl()'s HW_NCPU was hardcoded to 1 from before real pthreads existed — now a real SYS_sysctl round trip, so the worker pool sizes off an actual core count.
  • The dispatch_after timer thread intermittently never fired — root-caused to process-wide SIGALRM delivery landing on the wrong thread when more than one thread could be sleeping at once. Fixed by spin-polling the deadline instead of calling nanosleep() from a background thread.
  • Verified live: serial-queue FIFO ordering, a real __block byref capture, dispatch_once racing 8 concurrent threads down to exactly one run, and 4 concurrent tasks pushing 50,000 increments each under a semaphore to an exact 200,000 — zero lost updates.
