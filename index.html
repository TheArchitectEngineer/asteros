Boot order, bottom to top

Ten real layers, each one built to run the next.

Every layer below is genuine, ground-truthed source — no stand-ins. Tap a layer to see what it actually does and what it took to get there.

Custom UEFI bootloader
boot/ — hand-written, no gnu-efi
done
Parses the kernel Mach-O, builds Apple's flattened device tree by hand, strips EFI_MEMORY_RUNTIME before ExitBootServices, and jumps to _pstart. Apple's real boot.efi isn't open source, so this is a clean-room UEFI application built against clang + lld-link.
XNU kernel — Mach + BSD
src/xnu · xnu-6153.141.1
done
Apple's real open-source kernel, 14 patches deep to compile and boot on a modern toolchain — including replacing 9 sites of a 32-bit boot trampoline trick that modern ld now refuses outright. Real fork/exec/signals/VM, unmodified.
dyld — the dynamic linker
userland/dyld/ · from scratch
done
Real rebase/bind/export-trie resolution against genuine LC_DYLD_INFO_ONLY metadata. Fully position-independent — even the dylinker itself gets ASLR-slid by the kernel, so dyld has to rebase everyone else without ever fixing up itself.
Foundation + CoreFoundation + GCD
NSString ↔ CFString toll-free bridging, real dispatch_queue_t
done
A real object model: CFRetain/CFRelease refcounting, genuine toll-free bridged NSCFString, and a GCD built on real kernel-scheduled pthreads — serial queues, semaphores, dispatch groups.
launchd — PID 1
userland/launchd/ · real XML plist supervision
done
Loads /etc/launchd/daemons/*.plist, supervises KeepAlive respawns with real throttling, reaps orphans via wait4(-1, …), and drains a clean SIGTERM shutdown into reboot(RB_HALT).

How this gets built

The discipline is the point.

01

Root-caused, not guessed

Every panic gets attached to lldb over QEMU's gdbstub, or read straight out of a serial log, before a fix lands. The pthread realization bug, the EFI runtime-memory collision, the carry-flag syscall misread — all found by reading actual state, not by pattern-matching a Stack Overflow answer.

02

Real sources, patched — not reimplemented

The kernel is Apple's actual xnu-6153.141.1. The Objective-C metadata layout is ground-truthed field-by-field against otool output on real compiled .m files. When something has to be written from scratch — dyld, libobjc, CoreFoundation — it targets the real on-disk ABI, not an approximation of it.

03

Verified live, every single phase

"Done" means booted in QEMU with a growing regression checklist re-run in full — dyntest, systest, objctest, cftest, pthreadtest, foundationtest, dispatchtest — all still passing, confirmed via serial console or repeated screendump captures, not assumed from a clean compile.

04

v1 gaps, written down — not hidden

Spin-based mutexes instead of psynch, linear-array CFDictionary instead of a hash table, one global autorelease pool — every simplification is documented next to the code that makes it, with the reason it was an acceptable tradeoff today.

Phase 19 · latest verified milestone

Grand Central Dispatch, running on real threads

verified live in qemu

libdispatch.dylib now ships serial and concurrent dispatch_queue_t, dispatch_sync/async, semaphores, groups, and dispatch_after — built directly on Phase 16's real kernel-scheduled pthreads. The regression test pushes 4 threads through 50,000 increments each on the global concurrent queue under a dispatch semaphore and lands on an exact 200,000. Zero lost updates.
